## 0. このプロダクトの中核思想

### 0.1 タグライン

> **途切れても、戻ればいい。**

記録アプリのほとんどは「続けること」を価値にしている。
連続日数を表示し、途切れると赤く警告し、ストリークが0に戻る。

**その設計は、続けられない人を切り捨てている。**

ネコのては逆を取る。
続かないことを前提に設計し、**戻ってきた瞬間を最も大事に扱う。**

このタグラインは、LPのコピーであると同時に、
設計原則（P1）であり、実装される機能（F-10）でもある。

### 0.2 名前の由来

「猫の手も借りたい」の反転。
手が回らない人に、猫が手を貸す。

## 1. 一文定義

**発達特性のある人が、「今日の気持ち」「お金」「通院」を、
一日ひと手間で記録して、生活が回っている状態を保つためのアプリ。**

### 1.1 解決する課題

```
気分の波が読めない
      ↓
調子の悪い日に支払いを忘れる / 使いすぎる
      ↓
通院を飛ばす
      ↓
さらに調子が崩れる
```

既存アプリは、気分記録・家計簿・カレンダーを**別々**に提供している。
分かれているから、**三つとも続かない。**

ネコのては、この三つを**同じ一画面から入力できる**ことだけを狙う。

### 1.2 目標（検証可能・かつ挫折しない形で）

> **直近14日のうち、7日以上に記録がついている。**

**「7日連続」にしない理由**
厳密な連続目標は、一度途切れた時点で全て終わったと感じさせる。
**1日飛ばしても崩壊しない基準**にする。これが第0.1章のタグラインの、数値上の表現である。

## 2. 設計原則

| # | 原則 | 具体的な意味 |
|---|---|---|
| **P1** | **矯正しない / 途切れても、戻ればいい** | 「サボった」「未達」「連続◯日」を表示しない。空欄は空欄のまま。**離脱から戻った人を、最も歓迎する** |
| P2 | 判定しない | 診断・重症度スコアを出さない |
| P3 | 刺激は上下に調整できる | ひかえめ / ふつう / はっきり の3段階。ADHDとASDで最適が逆になるため |
| P4 | 中断に強い | 入力途中で離脱しても自動保存 |
| P5 | ひと手間で終わる | 1日の記録が3タップ以内で完了する |
| P6 | 情報を持たない | 制度・医療機関のマスタデータを保持しない（第7章） |
| P7 | 記録そのものが介入である | 助言・評価・励ましを返さない。記録して見返せることだけで自制心は上がる。アプリは**見せるだけ** |

### 2.1 P1 が最上位にある理由

本プロダクトの対象は、**続けられなかった経験を何度もしている人**である。

そこに「続けましょう」という設計を持ち込むと、
**過去の失敗をもう一度なぞらせることになる。**

だから P1 は、単なる配慮ではなく**最上位の原則**として置く。
他の原則と衝突した場合、P1 を優先する。

### 2.2 P7 が必要な理由

本アプリは「記録できるツール」ではない。
**記録する行為そのものが行動を変える**という原理に立っている。

計画を立てるより、記録する方が自制心は高まる。
だから本アプリは、アドバイスを返さない。**事実を見せることに徹する。**

この原則は、将来「AIがコメントを返す機能」を足したくなったときの**防波堤**として機能する。

## 4. 中核機能の仕様

### 4.1 F-01 今日の記録

| 項目 | 仕様 |
|---|---|
| 気分 | 5段階。数値ではなく猫の表情で選ぶ |
| メモ | 任意。1行。空欄で保存可 |
| 操作数 | 表情タップ → 保存 の**2タップ**で完了 |
| 未入力の日 | 「未記録」と表示しない。空欄のまま（P1） |
| 遡り入力 | 過去日も入力可。「途切れた」演出を出さない |

### 4.2 F-02 家計簿

| 項目 | 仕様 |
|---|---|
| 分類 | 7つ固定（住居 / 食 / 通信 / 交通 / 医療 / たのしみ / その他） |
| 入力 | 金額 → 分類タップ → 保存 の**3タップ** |
| 計算 | 合計・残額はすべて自動。暗算を要求しない |
| 主表示 | 「**今月あといくら**」を1数字で最上部に大きく |
| 警告 | 残額が少ないときは色のみ。音・振動は既定オフ |

### 4.3 F-04 カレンダー

| 項目 | 仕様 |
|---|---|
| 表示 | 月表示。日ごとに記録の有無を薄い色で表示 |
| 空白日 | **グレーアウト・×印を使わない。** ただ色がないだけ |
| 予定 | 通院日、支払日、その他 |
| 通知 | 前日・当日。既定はアプリ内バッジのみ |

### 4.4 F-05 通院メモ

医療機関のマスタは持たない。ユーザーが自分の通う先を登録する。

| 項目 | 仕様 |
|---|---|
| 登録内容 | 名称、次回予約日、メモ |
| 位置情報 | 任意。本人が登録した場所のみ地図に表示 |
| 持たないもの | 診療時間、休診日、医師情報、口コミ、検索 |

### 4.5 F-06 ふりかえり ＋ 回復の証拠

**目的**: 調子が落ちている本人に、判定でも励ましでもなく「事実」を返す。

| やらないこと | やること |
|---|---|
| 「3日記録がありません」 | 何も言わない |
| 「がんばりましょう」 | 何も言わない |
| 「危険な状態です」 | 何も言わない |
| — | **「去年の同じ時期も低めでした」** |
| — | **過去に同じ状態から戻った期間を、静かにグラフで示す** |

**実装仕様**

```
条件: 直近7日の気分平均が、その人の全期間平均を下回っている

表示: 過去に同様の落ち込みがあった期間を検出し、
      「そのあと◯日で戻っています」と事実のみ提示

禁止: 「大丈夫」「きっと良くなる」等の予測・保証は書かない
      データがない場合は、何も表示しない
```

**なぜこれが必要か**
自己嫌悪に陥っているとき、必要なのは励ましではなく**自分の過去の回復履歴という証拠**である。
本人のデータを本人に返しているだけなので、P2（判定しない）に反しない。

### 4.6 F-09 ひらくきっかけ設定

**問題**: 1日の記録が30秒で終わっても、**アプリを開かなければ0秒である。**

**解決**: 既存の習慣に紐づける。設定で1つだけ選ぶ。

```
  ┌──────────────────────────────┐
  │ [ 朝おきたら ▾ ] ネコのてをひらく │
  └──────────────────────────────┘

  選択肢: 朝おきたら / ごはんのあとに / おふろのあとに / ねるまえに
```

| 反映先 | 挙動 |
|---|---|
| 通知 | 選んだタイミングに送る（**希望した場合のみ**。既定オフ） |
| ホームの挨拶 | 「おはよう」「おつかれさま」等をトリガーに合わせる |
| 変更 | いつでも変更可。変更を咎めない |

**設定は必須にしない。** スキップできる。強制すると、その時点で離脱する。

### 4.7 F-10 おかえり画面（新規・最重要）

**このアプリの正念場は、離脱から戻ってきた瞬間である。**

タグライン「途切れても、戻ればいい。」を、実装として担保する機能。

#### 発動条件

```
最終ログイン日から 3日以上 経過して、再びアプリを開いたとき
```

#### 表示内容

```
┌────────────────────────────┐
│                            │
│           🐾               │
│                            │
│      おかえりなさい          │
│                            │
│   途切れても、戻ればいい。   │
│                            │
│   ┌──────────────────┐     │
│   │  きょうを記録する  │     │
│   └──────────────────┘     │
│                            │
│      あとで  ←小さく         │
└────────────────────────────┘
```

#### 絶対に表示しないもの

| 禁止 | 理由 |
|---|---|
| 「◯日ぶりです」 | 空白期間を意識させる |
| 「久しぶりですね」 | 同上 |
| 「記録が途切れました」 | P1 違反 |
| 「もう一度がんばりましょう」 | 励ましは P7 違反 |
| 空白期間のグラフ強調 | 失敗の可視化になる |

#### 仕様の要点

- 空白期間の**長さに関わらず、表示内容は同じ**（3日でも3ヶ月でも変えない）
- 「あとで」で閉じられる。閉じても咎めない
- 過去データはそのまま残っており、**何も失われていない**ことを示す
- この画面から「きょうを記録する」を押すと、**2タップで記録が完了**する

**設計意図**
戻ってきた人に必要なのは、説明でも謝罪の要求でもなく、
**何事もなかったかのように再開できること**である。

## 7. 制度・医療情報の扱い

### 7.1 手当・助成金の情報を載せない

**理由**
- 支給基準・金額は自治体ごとに異なり、年度で変わる
- 個人開発で全国分を正確に維持することは不可能
- 誤った情報により申請を諦める人が出た場合、取り返しがつかない

**代わりにすること**
S-11 相談先に、窓口への導線だけを置く。

```
・お住まいの自治体の障害福祉課
・相談支援事業所
・ハローワーク 専門援助部門
・発達障害者支援センター（都道府県別リンク）
```

### 7.2 医療機関のマスタを持たない

診療時間・休診日は頻繁に変わる。古い情報は、体調が悪い人にとって深刻な損害になる。
医療機関情報には、継続的に維持された信頼できる公開データソースが存在しない。

→ **本人が、自分の通う先を登録する。**

---

## 8. 外部サービスへの送客を行わない

対象には経済的に余裕のない人が含まれる。
支援を目的とする画面から有料サービスへ誘導する構造は、支援を装った送客になる。
第三者コンテンツの内容について、開発者は責任を負えない。

**ただし、知見を設計に活かすことは行う。** 送客と参照は別である。

| `(marketing)/layout.tsx` | LP用ヘッダー、OGP、**3Dの読込** | アプリ内タブ、業務データ |
| `(app)/layout.tsx` | 下部4タブ、バナー、**おかえり判定** | 3D、各機能固有の状態 |
| `today/layout.tsx` | 入力中の自動保存 | 家計簿の集計 |
| `money/layout.tsx` | 今月サマリの常時表示 | 気分の状態 |

### 9.2 `(marketing)` を親として分ける理由

**3Dライブラリをアプリ本体に混入させないため。**
Route Group を分けることで、`(app)` 配下のバンドルに Three.js が入らない。

### 9.3 おかえり判定を `(app)/layout.tsx` に置く理由

どの画面から起動しても発動させるため。
`today/page.tsx` に置くと、他画面から復帰した場合に発動しない。

### 9.4 `today` を独立した子にする理由

気分とお金を「今日」という同じ文脈で入力させるため。
別タブに分けると、ユーザーは別アプリとして認識し、片方しか使わなくなる。

### 10.1 RLS 方針

- 全テーブルで RLS 有効化
- `auth.uid() = user_id` のみ許可
- 共有機能を持たない（支援者ビューは v1 スコープ外）

### 10.2 目標判定と回復の証拠のためのビュー

```sql
-- 直近7日の気分平均と、全期間平均の比較（F-06）
-- および 14日中の記録日数（第1.2章の目標判定）
create view v_mood_trend as
select
  user_id,
  avg(mood) filter (where log_date >= current_date - 6)  as recent_avg,
  avg(mood)                                              as overall_avg,
  count(*) filter (where log_date >= current_date - 13)  as logged_in_14d
from daily_logs
where mood is not null
group by user_id;
```

`logged_in_14d >= 7` が第1.2章の目標達成条件。
**この数値はユーザーに表示しない**（P1）。開発側の検証指標としてのみ使う。

## 18. LP 設計

### 18.1 LPとアプリの役割分離

| | LP | アプリ本体 |
|---|---|---|
| 目的 | **理解させる** | **使わせる** |
| 見る回数 | 1回 | 毎日 |
| 許される刺激 | 高い | 極小 |
| 3D | **使ってよい** | 使わない |

**毎日開くアプリに動きが多いと疲れる。LPは1回しか見ない。だから3Dを使える。**

視覚的な対比ひとつで世界観を一瞬で伝える構成を取る。

### 18.2 LPの中心コピー（確定）

```
        途切れても、戻ればいい。
```

**このコピーを選んだ理由**
本プロダクトが他の記録アプリと最も違う点（連続を強制しない）が、一文で伝わる。
「猫の手も借りたい日に、猫が手を貸す。」は名前の説明に留まるため、サブコピーとして使う。

**LP・アプリ・仕様書の三箇所で、同じ一文を使う。**

| 場所 | 用法 |
|---|---|
| LP ファーストビュー | 中心コピー |
| アプリ S-13 おかえり画面 | 離脱から戻った人への一文 |
| 仕様書 第0.1章 / P1 | 設計原則 |

### 18.3 3Dの使用範囲（厳格に限定）

**3Dで表示するのは「猫の手」ひとつだけ。**

| 項目 | 仕様 |
|---|---|
| 対象 | 猫の前足（肉球側）のモデル1点のみ |
| 使わない箇所 | 背景、文字、UI、アイコン、装飾 |
| 配色 | **アプリ本体と同一のカラートークンを使用** |
| 質感 | マットな単色。光沢・反射を抑える |
| 動き | スクロール連動。自律的なループアニメーションを持たない |

**なぜ手だけか**
背景やUIまで3Dにすると、LPの世界観とアプリの世界観が乖離する。
「猫が手を貸す」というプロダクト名を、**手ひとつで説明する。**

### 18.4 必須の技術制約

| 項目 | 仕様 |
|---|---|
| モデル制作 | Blender → glTF 書き出し（**Blenderはアプリに含めない**） |
| 圧縮 | Draco 圧縮を適用 |
| ポリゴン数 | 10万ポリゴン以下 |
| 読込 | 遅延読込。ファーストビューの文字より後 |
| `prefers-reduced-motion` | **有効時は3Dを静止画（PNG）に差し替え** |
| WebGL非対応 | 静止画にフォールバック |
| バンドル分離 | `(marketing)` Route Group に閉じ、`(app)` に混入させない |

**`prefers-reduced-motion` への対応は必須。**
感覚過敏に配慮すると謳うプロダクトのLPが、動きを強制してはならない。

### 18.5 スクロール構成

| # | セクション | 内容 | 3D |
|---|---|---|---|
| 1 | ファーストビュー | **「途切れても、戻ればいい。」** 猫の手が画面下からゆっくり出る | **あり** |
| 2 | 課題 | 気分・お金・通院が別々になっている図 | なし（2D静止） |
| 3 | 解決 | 3つが同じ画面にある。実際のアプリ画面 | なし（実画面） |
| 4 | 体験 | 「2タップで終わる」。手が表情を選ぶ動き | **あり** |
| 5 | 思想 | 連続記録バッジを出さない理由。おかえり画面の紹介 | なし |
| 6 | 安全 | 診断しない / 助言しない / 情報を持たない | なし |
| 7 | CTA | 「はじめる」 | なし |

**3Dは 1 と 4 の2箇所のみ。**
多用すると「低刺激」というプロダクトの主張と矛盾する。

### 18.6 LPで書かないこと

- 「誰でも簡単に続けられます」等の効果の保証
- 医学的な効能の示唆
- 発達障害の説明・定義（当事者に説明は不要。非当事者向けの解説はスコープ外）
- 他アプリとの比較・批判
- 「毎日続けましょう」等、継続を推奨する表現（**P1違反**）
